## no-store implementation note

Because FastAPI's automatic 422 responses bypass handler code,
the no-store header MUST be installed via middleware or a custom
APIRoute subclass matched on path prefix /api/v1/consumption,
NOT inside individual handlers.


# Normalization Detail

Services perform string comparisons against ingested
timestamps. Ingestion serializes UTC via
_iso_utc (ingest/service.py:56). _validate_window normalizes
both bounds through the same datetime -> UTC isoformat path so
string comparisons in services remain correct regardless of the
caller's timezone offset.

# Rollout / Risk

- purely additive routes; zero changes to existing modules
  (app.py gets one registration call)
- largest risk: no-store middleware accidentally spanning other
  routes — mitigated by K18-negative assertion (other routes
  must NOT gain the header) added to the suite
- 31-day window cap is a new gate decision; recorded as such in
  the gate and tested explicitly
